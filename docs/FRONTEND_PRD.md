## 1. 文档定位

本文档描述网页端应当做成什么样，供设计与实现对齐使用。它不重复后端能力清单，
后端接口与数据契约见项目根目录 `README.md` 与 `PLATFORM_ROADMAP.md`。

读者：负责界面的设计者与前端实现者。实现载体是 `dashboard/index.html`、
`dashboard/styles.css`、`dashboard/app.js` 三个文件，保持零构建、零依赖。

## 2. 产品定位

本地优先的 Python 应用开发训练环境。数据存在本机，AI 能力可选接入。

三个不可动摇的产品立场：

1. 学生自己写代码，AI 是陪练不是代写。
2. 证据优先，结论要能追溯到具体测试函数与代码。
3. 一次只推进一步，界面不制造焦虑。

## 3. 核心使用场景

| 编号 | 场景 | 用户目标 | 成功信号 |
| --- | --- | --- | --- |
| S1 | 打开电脑继续上次的关卡 | 三秒内回到未完成的题 | 首屏直接出现当前关卡 |
| S2 | 读题、写代码、跑测试 | 一轮改动有明确反馈 | 运行后看到逐函数通过情况与耗时 |
| S3 | 卡住了，向 AI 要提示而不是答案 | 得到指向具体函数的最小提示 | 提示逐级加深，不直接给完整解 |
| S4 | 一道题反复失败，需要看问题出在哪 | 理解自己错在哪一类 | 看到 AI 复审、标准答案、代码快照、原始输出 |
| S5 | 学完一段，想知道薄弱点 | 拿到可执行的下一步 | 诊断给出知识点掌握度与补练建议 |
| S6 | 拿到新学科材料，想变成课程 | 从材料生成可练的关卡 | 蓝图与关卡进入学习路线 |
| S7 | 想围绕某个问题发散学习 | 把问题长成知识树 | 图谱可追问、可把节点变成正式练习 |
| S8 | 中途离开、换设备继续 | 进度与记录不丢 | 关闭页面后重开，状态复原 |

## 4. 信息架构

外壳分三层：左侧栏、内容舞台、悬浮伴学。

```
左侧栏 rail
  课程按钮（点击弹出：科目切换 + 模式切换）
  三格统计（完成 / 用时 / 今日）
  五个板块（练习 / 档案 / 伴学 / 工坊 / 设置）
  路线标题行（关卡计数 + 全屏按钮）
  路线列表（课程模式）或知识图（工坊模式）

内容舞台 stage
  练习 · 作答 / 讲义 / 协作
  档案 · 总览 / 诊断 / 补练 / 维护
  伴学 · 单一对话面
  工坊 · 图谱 / 编译（编译内含 新建 / 列表 / 蓝图）
  设置 · 模型 / 平台

悬浮伴学 widget
  默认收起为一枚圆形按钮，展开为紧凑对话面板
```

左侧栏的两个特殊状态：点击全屏按钮后左栏覆盖整页显示路线或知识图，点选任意关卡
后自动收起；点击收起按钮后左栏隐藏，舞台左侧留一枚细长按钮可再展开。

模式：课程模式与工坊模式。两种模式共享科目，但学习记录、诊断、补练、练习队列
按来源隔离，互不串显。

## 5. 页面清单

| 页面 | 入口 | 页面目标 | 主要模块 |
| --- | --- | --- | --- |
| 练习 | 左栏「练习」或路线中任一关卡 | 完成当前关卡 | 关卡头、模块进度、文件位置、二级页签、任务说明、运行面板、本次记录 |
| 档案 | 左栏「档案」 | 回看与诊断 | 概览指标、通过趋势、最近运行、掌握度、薄弱点、补练、维护 |
| 伴学 | 左栏「伴学」 | 围绕题目提问 | 工具栏、对话会话栏、已载入题目、消息列表、输入框 |
| 工坊 | 左栏「工坊」 | 生长知识或编译课程 | 思维关系图、创造式对话、节点详情、课程编译表单 |
| 设置 | 左栏「设置」 | 本机配置 | AI 服务表单、平台身份表单 |

## 6. 各页面模块结构

### 6.1 练习

**作答页签**

1. 关卡头：模块名（眉标）、关卡标题、一句话摘要、右侧状态胶囊与时间预算、刷新按钮。
2. 模块进度条：细轨道加「模块进度 n/m 关」文字，未开始时为 0。
3. 文件位置卡：根目录、题目说明、编码文件、自动检查三个路径行，右侧「复制路径」「导出」。
4. 二级页签：作答 / 讲义 / 协作。
5. 概念标签行：本关知识点。
6. 双栏区：左为任务说明（Markdown 渲染的题面），右为运行面板。
7. 运行面板：眉标「检查」、标题「运行测试」、尝试次数、动作行（运行 / 提示）、提示框、输出区。
8. 本次记录：只显示当前关卡的历史运行，每条含标题、时间、结果、耗时、知识点、
   逐函数结果、动作行（载入到对话 / 复制题目信息 / 复审）、一个「详情」折叠区
   （内含 AI 审查、标准答案、代码快照、原始输出）。

**讲义页签**：知识点面板，四格图文：它在解决什么、核心写法、关键点、常见误区。
内容优先读 AI 写过的 `lesson.json`，没有则回退内置知识表。

**协作页签**：协作方法论。一句话上下文加步骤卡；AI 写过 `mentor.json` 时替换为它给的步骤。

### 6.2 档案

| 子页 | 模块 |
| --- | --- |
| 总览 | 三格指标（累计运行 / 通过率 / 最近运行）、通过趋势条带、最近运行列表（每条可点进对应关卡，带复制题目信息与载入到对话） |
| 诊断 | 诊断工具条（说明 + 诊断按钮）、掌握度列表（知识点 + 百分比 + 趋势 + 轨道）、薄弱点列表 |
| 补练 | 补练建议卡（知识点、难度、题目、再练按钮） |
| 维护 | 四格数据指标、备份操作、AI 用量摘要、备份列表、生成关卡列表（归档 / 恢复 / 删除） |

### 6.3 伴学

1. 工具条：一句话说明，右侧「载入当前题目」「分析当前题目」「前往工坊」。
2. 对话面板：会话选择、对话名称输入、保存名称、清空消息、删除对话。
3. 已载入题目：上下文胶囊，可逐个移除或全部清除。
4. 消息列表：用户与助手气泡，助手消息渲染 Markdown。
5. 输入区：多行输入加发送按钮。
6. 悬浮形态：收起时为圆形按钮，展开后复用同一套消息与上下文。

### 6.4 工坊

1. 图谱子页：思维关系图（SVG 画布）、适配按钮、刷新按钮、创造式对话栏（输入 + 提问）、节点详情卡（标题、类型、说明、生成练习）。
2. 编译子页：新建（科目或主题、学习模式、知识材料、生成课程）、列表（已生成科目）、蓝图（目标、模块、活动）。

### 6.5 设置

1. 模型子页：API 密钥、Base URL、模型、超时秒数、历史记录上限、清除密钥勾选、保存、测试。
2. 平台子页：平台名称、默认领域、副标题、保存。

## 7. 视觉风格关键词

具体令牌、组件、页面布局和验收清单见 [UI_DESIGN_GUIDE.md](UI_DESIGN_GUIDE.md)。

**基调**：安静的暗色工作台。克制、精确、可信，像工程工具而不是营销页面。

| 维度 | 关键词 | 具体要求 |
| --- | --- | --- |
| 色彩 | 冷中性近黑、单一强调色 | 背景与表面用接近中性的深灰，不用纯黑也不用偏蓝灰；强调色只有一个，只出现在选中态、主操作与焦点环；绿只表示通过，黄表示待完成，红表示失败 |
| 层级 | 细描边加顶部高光 | 用一像素低对比边框与内侧顶部高光表达层级，不用大投影 |
| 字体 | 中文友好、三级字重 | 正文 15 至 16px，行高 1.7；次要信息不小于 12px；只用 400 / 600 / 700 三档 |
| 技术标签 | 等宽、克制 | 路径、函数名、步骤编号用等宽字体，可加大写字距 |
| 圆角 | 小于等于 8px | 卡片 8px，控件 6px，胶囊用全圆 |
| 留白 | 密而不挤 | 模块间距成体系，避免同一屏塞入过多同级卡片 |
| 动效 | 短、可预期 | 过渡 140ms 左右，只用于状态变化，遵循系统减少动态偏好 |

反面清单：不用渐变装饰、不用光斑、不用大圆角包裹整块、不做整屏单色系、不在标题上
加无意义的小标签。

## 8. 交互规范

**命名**：导航与页签统一两个字，动作统一动词，同一动作只用一个词。运行指跑测试，
诊断指批量学习诊断，复审指对单条记录的 AI 代码审查，载入指把题目带入对话。

**异步操作**：进入进行中状态时按钮禁用并改写文案（运行中、诊断中、生成中、思考中），
结束后恢复原文案；错误以内联文本呈现，不用弹窗。

**破坏性操作**：删除或恢复练习、清理记录、清除密钥、删除对话必须二次确认，
确认文案要写明影响范围。

**AI 写入**：AI 通过工具修改内容后，界面要刷新受影响区域，并在聊天里留下一条
简短回执（改了哪个关卡、写了哪类内容）。

**刷新**：每个板块头部只有一个刷新入口，作用域跟随当前页签，避免同一屏多个刷新按钮。

**键盘**：页签支持方向键切换，按钮有可见焦点环，Esc 关闭浮层与菜单。

## 9. 空状态、加载与错误

**空状态统一句式**：说明为什么为空，再说明点哪里可以产生内容。

| 位置 | 文案方向 |
| --- | --- |
| 本次记录 | 这道题还没有记录。点一次「运行」，这里会保存结果、AI 审查、标准答案与代码快照 |
| 总览趋势 | 完成一次运行后，这里会显示每次通过的详情 |
| 掌握度 | 还没有测试级数据。完成一次运行后，这里会按知识点统计 |
| 薄弱点 | 暂时没有识别到稳定的薄弱知识点 |
| 补练 | 当前没有需要生成的补练题 |
| 生成关卡 | 还没有由 AI 生成的正式补练关卡 |
| 备份 | 还没有备份 |
| 对话 | 可以直接提问，也可以先载入一道题目的压缩上下文 |
| 工坊图谱 | 还没有知识支点。在右侧提问，让这棵树开始生长 |
| 科目无内容 | 该科目还没有可运行练习 |

**加载**：首次进入显示居中提示「正在读取学习进度…」；切换关卡时保留页面骨架，
只在加载区显示状态，不整页闪烁；按钮级加载见第 8 节。

**错误**：连接类错误要翻译成人能懂的话并给出下一步，例如系统拒绝对外连接时，
提示可能是运行环境禁止联网或防火墙拦截，并指向 `python network_check.py`，
不要直接把 `WinError 10013` 抛给用户。

## 10. 移动端适配

断点：1180 / 1080 / 900 / 760 / 520。

| 宽度 | 布局变化 |
| --- | --- |
| 1180 以下 | 左栏收窄，双栏练习区改单栏，统计字号下调 |
| 900 以下 | 左栏改为浮层抽屉并默认隐藏，舞台铺满，页面顶部留展开按钮 |
| 760 以下 | 页头与工具条纵向排列，表单改单列，卡片内边距收紧，二级页签横向滚动 |
| 520 以下 | 统计与指标改为更紧凑的排布，标题字号下调 |

触控要求：可点区域不小于 40px；抽屉展开后内部滚动，不把页面顶长；全屏路线在
窄屏下按单列排布。

## 11. 无障碍

1. 所有图标按钮必须有 `aria-label`。
2. 焦点环可见，且颜色与背景对比足够。
3. 正文与背景对比达到 AA，次要文字不低于 12px。
4. 状态变化（运行结果、诊断完成）通过 `aria-live` 播报。
5. 提交类控件用 `type` 明确语义，回车可提交。
6. 尊重 `prefers-reduced-motion`。

## 12. 组件清单

按钮（主 / 次 / 图标 / 微型）、页签、胶囊（状态 / 计数 / 供应商 / 上下文）、
面板（含标题行与动作位）、表单字段、下拉、多行输入、折叠区、消息气泡、
指标卡、进度条、列表项（关卡 / 记录 / 补练 / 备份）、图谱节点、抽屉与浮层、空状态块。

## 13. 验收要点

1. 五个板块与全部子页签可达，切换后页头标题与说明同步变化。
2. 同一动作在全站只有一个名字、一个入口。
3. 每页只有一个刷新入口。
4. 所有列表在无数据时显示规定的空状态文案。
5. 390 / 768 / 1024 / 1440 四档宽度无横向滚动、无控制台报错。
6. 断网或禁用网络时，界面给出可执行的解释而不是原始错误码。
7. 键盘可完成切换板块、切页签、运行、提问四项主要操作。

## 14. 待决问题

1. 练习页是否改为三栏常驻（说明 / 编辑运行 / 记录），取代当前纵向卡片流。
2. 结果区是否由嵌套折叠改为标签页（测试结果 / 标准答案 / 代码快照 / 原始输出）。
3. 路线视图是否默认只展开当前与相邻模块，而不是铺开全部模块。
4. AI 写入内容是否需要显式的确认与撤销入口。
5. 是否需要浅色主题，以及它与现有语义令牌的映射关系。
