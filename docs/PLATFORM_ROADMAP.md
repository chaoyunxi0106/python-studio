# Python Studio 架构演进路线

> 文档导航：[README.md](README.md)

## 当前分层

### 内容层

- `curriculum/`：总大纲、模块地图和路线顺序。
- `exercises/`：正式课程、隐藏进阶关卡和 AI 动态补练。
- `projects/`：项目实践入口。

### 执行层

- `checker.py`：运行 `pytest` 或 `unittest`。
- `test_analysis.py`：把测试输出解析到具体函数和知识点。
- `practice_pack.py`：把受约束的 AI 练习包转换为正式关卡。

### 证据层

`store.py` 使用 SQLite 保存：

- 每次运行、测试级结果和代码快照。
- AI 对具体代码的审查。
- 当前补练队列、诊断快照和趋势。
- 独立聊天会话、消息和题目上下文。

### AI 层

- `companion.py`：代码审查、学习诊断、动态出题和聊天。
- `context_export.py`：构造压缩后的题目上下文。
- `config.py`：从本机 `.env` 读取 DeepSeek 配置。

### 界面层

- `server.py`：本地 HTTP 接口和静态资源服务。
- `dashboard/`：练习、学习记录、AI 伴学和维护界面。
- `cli.py`：终端检查、提示和进度入口。

### 2026-10 框架优化

- 备份、恢复和维护已绑定当前科目工作区，支持跨科目隔离和 journal 恢复。
- 课程/工坊目录统一 `origin` 语义，工坊记录和练习不再混入课程目录。
- 伴学 AI 生成练习会写入 `subject_id/origin/stage`，无效模块编号会映射或进入未归类阶段。
- 题目标题按课程正式题、工坊题、补习题分类存储，并记录课程、模块和模块关卡。
- 工坊节点与边增加 `session_id`，第 8 版迁移兼容已有数据库。
- 练习执行统一使用 `execution.py`，限制超时、输出和环境。
- 模型调用统一经过 `providers/deepseek.py`，集中处理错误和 JSON。
- 学习诊断与概念题评估已拆入服务层。
- 浏览器端 API 客户端和 Markdown 工具已拆入 `dashboard/core.js`。

## 当前主要风险

### 1. 服务端和 AI 模块持续膨胀

- `server.py` 同时承担路由、业务编排、文件读取和响应组装。
- `companion.py` 仍包含诊断、出题、代码审查和聊天；网络适配已移出。
- 继续增加模型能力后，会很难测试和维护。

建议拆分为：

```text
api/routes/
services/learning.py
services/practice.py
services/chat.py
providers/deepseek.py
```

### 2. 数据库迁移仍是零散逻辑

当前通过 `CREATE TABLE IF NOT EXISTS` 和少量 `ALTER TABLE` 维持兼容。

建议增加：

- `schema_version` 表。
- 按序号执行的迁移文件。
- 启动前自动备份。
- 迁移失败自动回滚或停止服务。

### 3. AI 调用没有任务队列和成本记录

当前模型调用多数是同步请求。

建议补充：

- AI 任务表：pending、running、completed、failed。
- 模型、耗时、输入输出 token、费用记录。
- 重试次数和错误分类。
- 相同输入的分析缓存。
- 后台任务状态在网页端可见。

### 4. 没有显式知识点图谱

当前知识点主要来自题目 `concepts` 和 AI 结论。

建议建立：

```text
skills
skill_prerequisites
exercise_skills
student_skill_state
```

这样可以进行：

- 前置知识阻断。
- 掌握度传播。
- 跨章节遗忘检测。
- 更稳定的补练推荐。

### 5. 练习定义缺少独立版本

题目结构目前依赖约定和测试代码。

建议：

- 为每个练习增加 `schema_version`。
- 使用统一练习 JSON Schema。
- 提供题目创建、校验和预览命令。
- 在测试流程中校验所有 `meta.json`。

### 6. 生成代码的执行安全边界

模型生成测试代码已被限制，但学生代码仍在本地普通进程中执行。

本地单用户阶段可以接受。若未来提供网络服务，应增加：

- 容器或进程沙箱。
- CPU、内存、时间和文件系统限制。
- 网络隔离。
- 输出大小限制。

### 7. 学习数据缺少备份和恢复

SQLite 当前是单点数据源，工作区级备份和恢复已完成首版；仍需增加定时备份、保留策略和跨设备导出。

建议增加：

- 一键导出 ZIP。
- 定时备份和保留策略。
- 从备份恢复。
- 可选导出 JSON 学习档案。

### 8. 前端不断增长后的组件化

`dashboard/app.js` 和 `styles.css` 已包含大量视图逻辑；API 客户端和 Markdown 工具已拆到 `core.js`。

建议在继续扩展前：

- 拆分 API client。
- 拆分练习、记录、伴学、聊天和设置模块。
- 使用事件总线或状态容器。
- 增加基础端到端测试。

## 分发边界

本平台不建设多用户、云端同步、账号权限和远程判题服务。

未来共享方式为 GitHub 开源：

- 仓库只包含程序、课程、练习模板和示例数据。
- 每位学习者在本机运行，并配置自己的 DeepSeek 密钥。
- `.env`、`data/`、个人学习数据库和备份不进入仓库。
- 个人学习档案通过本地备份文件迁移。
- 不提供集中式用户数据存储。

## 推荐下一阶段里程碑

1. 增加数据库迁移、备份和学习档案导出。
2. 将 `server.py` 拆成路由层与服务层。
3. 为 AI 调用增加任务状态、缓存和 token 记录。
4. 建立知识点关系和跨章节掌握度。
5. 完成模块 3、4 的课程与练习。
6. 为题目定义 Schema 和自动校验。
7. 按 GitHub 开源模板方式完善安装、升级和发布流程。
